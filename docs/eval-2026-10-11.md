# Eval — tool selection by local models (2026-10-11)

`npm run eval` (scripts/eval/run-eval.mjs), 30 prompts in `scripts/eval/cases.json`
(23 apply to `core`). Scored on the FIRST tool call: right tool, right arguments.
LM Studio local server, RTX 5090, context 32 768, temperature 0, one run per case.
Figma is not touched. Raw results in `.eval/*.json` (gitignored).

Qwen's one failure (core, component + instance): without `create_component`
in the profile it wrote `query(root, …)` copied literally from an error hint,
then `figma.getNodeById` (sync), then invented `frame.createComponent()`, and
finally ran out of output tokens while reasoning. On a re-run it passed in 8

…)` example; "not a function" now lists the correct method names).

Typical traces: `find_nodes > set_fill x3` for the recolor, `find_nodes >

has fewer structured tools, and from structured calls when it has more; both
pass the check either way. Gemma uses roughly half the tokens of Qwen for the
same tasks, mostly because it reasons less before each call.

## Variance: 3 runs per case, temperature 0 and 0.7

Same first-call eval, every case repeated three times.

| Model | Profile | t=0, tool / tool+args | t=0.7, tool / tool+args |
|-------|---------|------------------------|--------------------------|
| Qwen3.8 27B | core | 69/69 / 69/69 | 69/69 / 69/69 |
| Qwen3.8 27B | core + skill | 69/69 / 69/69 | 69/69 / 69/69 |
| Qwen3.8 27B | full + skill | 90/90 / 90/90 | 87/90 / 87/90 |
| Gemma 4 31B | core | 66/69 / 63/69 | 66/69 / 63/69 |
| Gemma 4 31B | core + skill | 66/69 / 63/69 | 66/69 / 63/69 |
| Gemma 4 31B | full + skill | 90/90 / 90/90 | 90/90 / 90/90 |

- At temperature 0 the three runs are identical, so "3 runs" adds nothing
  there; at 0.7 the picture barely moves. Tool choice is stable, not lucky.
- Qwen's three misses at 0.7 are "look before you leap" choices:
  `list_workspaces` before `import_image_to_figma` (twice) and
  `get_current_page` before `resize_node`. The first is arguably correct and
  the case now accepts it.
- Gemma's misses are the same every time: `bridge_status` for "what is on
  the page", `list_pages` or `bridge_status` for "create a variable" in the
  core profile (no variable tools there), and `find_nodes` called with
  `name_pattern: ".*"` (once `"TEXT"`) instead of `type: "TEXT"`. The
  `find_nodes` description and `type` enum were rewritten for this; Qwen
  picked it up, Gemma did not. Server-side mitigation: a `name_pattern` of
  `.*` is now ignored, so the call still returns every node and the model
  filters by `type` in the result.

## What the numbers say

- **Both models pick the right tool almost always.** The `full` profile with
  88 tools scores 100% on tool choice for both. The 27-tool `core` profile
  scores lower only because two prompts (make a component, create a variable)
  have no structured tool there and the models must fall back to `use_figma`;
  Gemma answers in prose instead, Qwen writes the JavaScript.
- **Context cost is the real trade-off.** `full` costs 12.3k tokens per turn
  for Qwen and 9.6k for Gemma before any conversation; `core` costs 3.9k / 2.9k.
  The skill adds ~2.7k. On a 32k window `full + skill` leaves ~17k for the
  actual work; on 16k it does not fit at all.
- **The skill fixes API mistakes, not tool choice.** Without it Qwen wrote
  `figma.getNodeById(...)` (sync, fails under dynamic-page); with it,
  `await figma.getNodeByIdAsync(...)`. Gemma's `find_nodes` call improved from
  `use_figma` to the right tool but still passed `name_pattern: ".*"` instead
  of `type: "TEXT"` — a description-level fix candidate.
- **Wording matters more than schema size.** The first skill draft said
  "call `bridge_status` first"; both models then called it for *every*
  prompt (Qwen: 3/23 correct). After rewording to "once per session or
  after a failure", Qwen went to 22/23. The tool description was changed the
  same way.

## Recommendation for Hermes

- Qwen3.8 27B: `design` profile (62 tools, ~8k tokens): 6/6 live, 100% first-call; `full` only on 32k+ contexts and short sessions.
- Gemma 4 31B: `design` or `full + skill`; 6/6 live on every profile and about half of Qwen's token use.
- Keep the skill enabled in both cases for `use_figma` correctness.

## Fixes that came out of this run

- SKILL.md §1 and the `bridge_status` description no longer tell the model
  to check connectivity before every action.
- Eval cases for "component" and "variable" accept the phase-8 structured
  tools as well as `use_figma`.
- Qwen must be loaded with `--context-length 32768`; LM Studio's JIT reload
  after a server restart falls back to 8192 and `full` requests fail with
  `exceed_context_size_error`.
