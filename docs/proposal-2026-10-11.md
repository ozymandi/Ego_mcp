# Пропозиція покращень — gemma-figma-mcp (11.10.2026)

Статус: чернетка для дизайнера. Нічого не реалізовано, чекає на вибір пунктів.

## Контекст

- У сервері зараз **66 тулів** (README/help кажуть «31» — застаріло). Фази 1–7 зроблені.
- Серіалізований список тулів = **35 445 байт ≈ 10 000 токенів** ще до того, як LM Studio загорне його в chat-template моделі (реально 12–15k). Для Gemma 4 / Qwen3.8 27B на 32k контексті це 30–45 % бюджету до першого повідомлення.
- Найважчі схеми: `create_flowchart` (1.4 KB), `import_image_to_figma`, `generate_code_connect`, `get_image`, `mermaid_to_canvas`, `create_text`.
- Офіційний Figma MCP (жовтень 2026): `get_design_context`, `get_metadata` (компактний XML-outline), `get_screenshot` (cap 1024px), `get_variable_defs`, `use_figma` (з рантайм-хелперами `node.query`, `node.set`, `createAutoLayout`, `node.screenshot()`, `placeholder`, помилки з `safeToRetryWithoutCanvasRead`), `search_design_system`, `get_libraries`, `download_assets` (≤20 нод), `upload_assets`, `create_new_file`, `generate_diagram`, `get_motion_context`, Code Connect (map/suggest/send), генеративні плагіни + шейдери, `generate_image` (кредити), Weave (платно). Плюс 13 skills (`figma-use` з 18 «критичними правилами» і gotchas).
- Plugin API 2026: слоти (`createSlot`, GA 06.2026), Motion API (06.2026), змінні типів EASING/TIMING (08.2026), шейдери як fill/effect. REST 2026: folders v2 (projects deprecated 08.2026), `VariableComposedColor` (09.2026), `page_size` для team components до 1000 (07.2025), oEmbed.
- Локальні моделі: Gemma 4 26B-A4B / 31B — tool calling є, контекст 256k, мультимодальні; у форумах скарги на зациклення тул-колів і провал при короткому контексті. LM Studio пише прямо: сервери, зроблені під хмарні асистенти, «з'їдають багато токенів і викликають overflow».

Три реальні проблеми для локальних моделей: (1) вибір серед 66 схожих тулів, (2) написання правильного JS для `use_figma` (всі gotchas з офіційного skill — font load, 0–1 кольори, HUG/FILL, `setCurrentPageAsync`), (3) відповіді, що підривають контекст (`get_file`, base64 у `get_screenshot` при scale 2).

## P0. Клієнт — Hermes Agent (уточнено 11.10.2026)

Основний пайплайн: Hermes Agent (Nous Research) з локальними моделями через LM Studio. Що це означає для MCP:

- Hermes реєструє кожен тул як `mcp_<server>_<tool>` і **кладе всі схеми в контекст без відкладеного завантаження**. Токен-дієта потрібна. Але фільтр `tools.include` / `tools.exclude` (глоби) в `mcp_servers` дає профілі без змін у сервері — P1.1 переносимо з коду в README як готові `include`-списки (`core`, `design`, `full`). Коротка назва сервера в конфігу (`figma`), бо вона стає префіксом кожного тулу.
- Результати `mcp_*` понад 50 000 символів Hermes скидає на диск і лишає прев'ю. Це страховка, не заміна P1.3–P1.4: 50k прев'ю для 27B усе одно дорого.
- Картинки з тулів Hermes додає vision-моделі (стискає до `vision.embed_target_bytes`, максимум 4 на результат). Inline-скріншоти працюють; наш cap 1024 px зменшує байти ще до Hermes.
- **Скіли**: Hermes має SKILL.md з прогресивним завантаженням (у промпті тільки name+description, повний текст — за викликом) і сам створює/патчить скіли (`/learn`, `skill_manage`). Тому `help` як тул — не той канал. Правильно: репозиторій постачає `skills/figma-mcp/SKILL.md` + `references/gotchas.md`, `references/snippets.md`, `references/tools.md`, користувач підключає через `skills.external_dirs`, у frontmatter `metadata.hermes.requires_toolsets: [mcp-figma]`, щоб скіл був видимий лише коли сервер підключений. Hermes далі накопичує власні скіли поверх нашого (наприклад, «як зібрати картку з інстансів»). Тул `help` лишаємо для інших клієнтів.
- MCP prompts / resources Hermes обгортає в `get_prompt` / `read_resource` — наш `figma_help` prompt доступний, але SKILL.md кращий.
- `supports_parallel_tool_calls` не вмикати: канвас-операції в плагіні послідовні.
- `lazy: true` в конфігу — сервер стартує при першому виклику, зручно разом з автостартом демона.

### Матриця клієнтів (пріоритет від дизайнера, 11.10.2026)

| # | Клієнт | Моделі | Що впливає на дизайн MCP |
|---|--------|--------|--------------------------|
| 1 | Hermes Agent | локальні (Qwen3.8 27B, Gemma 4) на LM Studio | усі схеми в контексті; фільтр `tools.include`; SKILL.md із прогресивним завантаженням; агент сам накопичує скіли |
| 2 | Claude Code, Codex | великі LLM | Claude Code відкладає MCP-тули (ToolSearch), читає `.claude/skills/*/SKILL.md`, використовує tool annotations; Codex читає `AGENTS.md` і теж має папку скілів (перевірити формат при реалізації) |

### Спостереження з живої сесії Qwen (11.10.2026, Threads-клон)

- Іконки в рядку дій (лайк, відповідь, репост) вийшли як риски й знаки «≡»: модель не має способу вставити векторну іконку і підставляє текст/лінії. Потрібен `insert_icon` (вбудований набір ~60 іконок Lucide як SVG-рядки → `createNodeFromSvg`) і загальний `create_from_svg(svg, x, y, parent_id)`. Додано в P3.4.
- Три скріншоти поспіль того самого фрейму з однаковим розміром файлу: канвас не змінювався, а модель витратила три виклики і три картинки контексту. Потрібен дедуп: хеш байтів по ноді, якщо збігся — відповідь «unchanged since HH:MM», без inline-картинки. Додано в P1.5.
- `daemon.log` відсутній: демон запущено через `start-bridge.bat`, а не через Scheduled Task, тож лог тул-колів (P4.2) має писатися у файл незалежно від способу запуску.

Новий пункт **P2.0: seed-скіл для Hermes** (SKILL.md + 3 reference-файли, стислі правила з офіційного `figma-use`, карта тулів по задачах, 8–10 сніпетів для `use_figma`, патерн «запис → скріншот → перевірка»). 3–4 год. Це найдешевший пункт із найбільшим ефектом, бо агент читає його лише коли треба і добудовує сам.

## P1. Токен-дієта (найбільший ефект для локальних моделей)

1. **Профілі тулів**: для Hermes — готові `tools.include` списки в README (`core` ~15 тулів: bridge_status, get_current_page, get_selection, find_nodes, get_node_spec, get_screenshot, use_figma, create_frame/text/rectangle, set_fill, set_text, move/resize, set_auto_layout; `design` + canvas + variables + instances; `full`). `FIGMA_MCP_PROFILE` у `.env` — лише для клієнтів без фільтра (чат LM Studio), другою чергою.
2. **Скорочення схем**: описи до 1 речення, enum замість вільних рядків, прибрати дублі параметрів; ціль ≤ 20 KB для `full`, ≤ 6 KB для `core`.
3. **Ліміт розміру відповіді**: єдиний `truncate(result, max_chars)` з маркером `…[truncated, N more]` + параметр `max_chars` на важких тулах (`get_file`, `get_node`, `read_text_file`, `find_nodes`).
4. **Компактні відповіді REST**: `get_node`/`get_file` за замовчуванням повертають outline (id, name, type, bounds, text, fills summary) у стилі офіційного `get_metadata`; сирий JSON — лише за `raw=true`.
5. **Скріншоти**: моделі мультимодальні, тому inline лишається увімкненим. Замість вимкнення — cap 1024 px по більшій стороні (як в офіційному), дефолтний scale 1 замість 2, JPG за замовчуванням для великих фреймів (менше байтів за ту саму картинку). Параметр `max_px` для явного контролю. Дедуп: якщо хеш експорту ноди збігається з попереднім — повертати «unchanged since HH:MM» без картинки. Ретеншн папки `screenshots/` (наприклад, 50 останніх).

Оцінка: 6–8 год.

## P2. `use_figma` для моделей, що пишуть слабший JS

1. **Прелюдія в плагіні** (виконується перед сніпетом): поліфіли `node.query(selector)` (підмножина: тип, `[name=…]`, `[name*=…]`, `>` і нащадки), `node.set(props)`, `figma.createAutoLayout(dir, props)`, `loadFontsFor(node)`, `hex(color)` → 0–1. Це знімає половину gotchas з офіційного skill.
2. **Нормалізація помилок**: плагін ловить типові винятки і додає `hint` + `safe_to_retry` (unloaded font → «викликай await loadFontsFor», `Setting figma.currentPage` → «setCurrentPageAsync», HUG/FILL → «спочатку appendChild», колір > 1 → «поділи на 255»).
3. **Авто-збір створених нод**: прелюдія патчить `figma.create*`/`appendChild` і додає `created_ids`, `mutated_ids` у відповідь навіть якщо модель їх не повернула.
4. **help("gotchas")** — стиснута версія 18 правил офіційного skill (≤ 1.5 KB) + 5 готових сніпетів; `help` як MCP-prompt уже є — додати туди той самий текст.
5. **Авто-скріншот після запису** (опція `screenshot: true` у canvas-тулах і `use_figma`): відповідь містить текстовий результат плюс картинку створених нод. Модель з vision одразу бачить, що вийшло, без окремого виклику. Дефолт вимкнений, щоб не роздувати контекст у довгих сесіях.
6. **Таймаут/зациклення**: ліміт часу сніпета вже є; додати ліміт кількості створених нод за виклик (env, за замовчуванням 2000) як запобіжник від `while(true)`.

Оцінка: 8–10 год.

## P3. Закрити функціональні прогалини проти офіційного MCP

Через плагін (працює на будь-якому плані, на відміну від REST Variables, де потрібен Enterprise):

1. **Змінні**: `list_variable_collections`, `get_variables(collection_id?)`, `create_variable`, `set_variable_value(mode)`, `bind_variable(node_id, field, variable_id)`, `get_variable_defs(node_id)` (що реально прив'язано до ноди — аналог офіційного). Разом із типами EASING/TIMING і `COLOR_OPACITY` scope. 6–8 год.
2. **Компоненти та інстанси**: `create_instance(component_key | node_id, x, y, parent_id)` через `importComponentByKeyAsync`, `set_instance_properties`, `swap_instance`, `create_component(node_id)`, `combine_as_variants`, `detach_instance`. Без цього модель не може «зібрати екран із дизайн-системи» — головний сценарій офіційного `figma-generate-design`. 6–8 год.
3. **Сторінки і навігація**: `list_pages`, `set_current_page`, `zoom_to(node_ids)`; у `bridge_status` повертати file name, editorType, поточну сторінку. 2 год.
4. **Стилі, властивості, іконки**: `set_corner_radius`, `set_opacity`, `set_effects` (shadow/blur), `apply_text_style`/`apply_paint_style`, `set_constraints`, `set_layout_child` (HUG/FILL/FIXED з перевіркою контексту); `create_from_svg(svg, x, y, parent_id)` і `insert_icon(name, size, color)` з вбудованим набором Lucide (MIT). 6–7 год.
5. **`get_node_spec(node_id)`** — аналог `get_design_context` без генерації коду: компактний JSON/MD зі структурою, auto-layout, відступами, типографікою, кольорами (hex), прив'язаними змінними і текстами. Великі моделі з цього напишуть код самі; локальним це дешевше за сирий REST-JSON. 4–6 год.
6. **Експорт у файли**: `export_nodes_to_workspace(node_ids, format, scale, workspace, path)` — аналог `download_assets` поверх плагіна + sandbox workspaces; зворотне (`upload_assets`) уже є як `import_image_to_figma`. 2 год.
7. **REST-дрібниці**: `get_file_meta`, folders v2 (`list_team_folders`, `list_folder_files`) для пошуку file key за назвою; `page_size` до 1000 у team-тулах; `get_image_fills`. 2–3 год.
8. **Motion / слоти** (нові API 2026): `get_motion_context(node_id)` читання keyframes/animation styles; `create_slot`. Низький пріоритет, 3–4 год.

Поза межами (хмарні фічі Figma, не відтворити локально): `generate_image`, Weave, генеративні плагіни, шейдери-на-кредитах, `generate_figma_design` з браузера.

## P4. Перевірка якості на локальних моделях

1. `scripts/eval/`: 20–30 промптів («створи картку 320×200 з заголовком», «перефарбуй усі прямокутники», «що на сторінці») → запуск через OpenAI-сумісний API LM Studio з нашим tool list → метрики: правильний тул обрано, валідні аргументи, кількість кроків, успіх у Figma. Запускати для Gemma 4 26B-A4B, 31B і Qwen3.8 27B, по профілях `core`/`full`. Це єдиний спосіб довести, що P1–P2 реально допомагають. 5–6 год.
2. Логування тул-колів у `daemon.log` (tool, ms, bytes in/out) для діагностики.

## P5. Господарське (дрібне, без нової поведінки)

- README/help: «31 tools» → фактичне число; «phases 2, 4–6 planned» → done; список тулів генерувати скриптом з коду, щоб не розходився.
- MCP tool annotations (`readOnlyHint`, `destructiveHint`, `idempotentHint`) — клієнти на кшталт Claude Code використовують їх для підтверджень; LM Studio ігнорує, шкоди немає.
- `.env.example`: описати `FIGMA_BRIDGE_PORT`, `FIGMA_BRIDGE_URL`, майбутній `FIGMA_MCP_PROFILE`.
- `protocol.ts`: прибрати невикористаний `async` у `ExecPayload`.

Оцінка: 1–2 год.
